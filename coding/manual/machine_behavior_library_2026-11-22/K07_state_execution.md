# K07 动态状态、记忆与外部执行

连接A7、J13、J14、J20、G5。本章补的是运行协议：什么对象在变化，谁能看到什么，动作是否真的执行，结果如何进入下一步。不开发平台，也不把“讨论过工具”记成“运行过工具”。

<a id="k07-01"></a>
## 01 从代码文本到真实结果

给每次执行绑定程序/规则版本、输入、解释器或求解器、依赖及测试。先提取需要执行的代码块，保留原输出和提取规则；交给对应运行器后，分别回收返回值、标准输出、异常、退出状态和测试结果，再按声明的评分规则判断。生成了代码、代码可解析、运行成功和测试通过是四个不同事实。

例如assert通过只支持所给测试；程序返回正确数值也不保证所有路径正确。article_030的首次错误定位需区分思路、实现及缺库，不能把运行环境缺依赖直接记为逻辑错误。为本地生成代码运行设置与任务相称的时间/资源限制，避免一次死循环阻断整批；不额外设计与本项目无关的公开服务防护。

最小执行记录：任务ID→生成文本→实际执行片段→输入→运行器版本→输出/异常→测试→评分。涉及专门逻辑、CSP、空间或数值方法时，运行器接口不替代[K06](K06_cognitive_causal.md)中的领域规则。

<a id="k07-02"></a>
## 02 状态转移和行动反馈

用`state_t → observation_t → model_action_t → parsed_action_t → transition → state_(t+1)`表达一轮。环境持有权威状态；模型说“我已移动”不改变棋盘。转移函数检查合法动作、更新状态、生成奖励/观测与终止标记。分别定义非法、无法解析、超轮次、胜负和终局，保留失败轨迹而非只留成功行动。

动态bandit还要定义奖励分布、切换时点、强制选择阶段、行动后才可见的奖励及随机状态；抽到的奖励是一次观测，不是当前真实均值。多agent同时行动时，先收齐同轮动作再执行还是顺序执行必须固定，避免后行动者意外看到额外信息。

article_003的horizon、two-step和BART各有转移规则；article_194用实际游戏环境及子目标进度。合法行动、任务完成与子目标评分仍是不同输出，环境跑通不能补齐未报告的评分权重。

同轮私密行动要以同一个轮初状态生成每个角色的观测，把各自提交暂存，全部收齐后才执行合并更新。若实验有意让角色依次观察前人的结果，应记录次序及每人的实际观测版本。第128篇的私密提交与公开讨论发生在不同阶段。

<a id="k07-03"></a>
## 03 私密信息与群体意见

为每个agent明确私有状态、公共状态、可读消息和可写字段。每轮先向本agent提供它应见的信息，收回私密笔记与公开消息，只把公开字段转发；保存两者以便审计，但下一agent的提示不自动包含私密笔记。阶段转换、历史截断及终止必须沿同一协议。

article_005的双方终止短语只触发结束判断，soft agreement还检查各议题可接受报价是否相同，hard agreement再要求公开同意；结束不等于有效成交。私密笔记是模型生成文本，不是直接读取内部思维。

群体协议另定义成员身份、发言次序、每人可见意见、讨论轮数、投票规则、并列处理和共同反馈生成。article_010的群组多数决定与合成一份评论不是把所有成员当独立个体求均值；共同评论进入后续环境形成依赖，统计单位需保留群组/时间结构。

<a id="k07-04"></a>
## 04 检索证据与上下文回填

保存实际查询、检索时间/服务、返回排序及选取规则，区分snippet、网页全文、结构化数据和检索服务自己生成的回答。对全文清理保留来源对应，记录截断、去重和重排；把选中材料连同必要出处送入模型，再保存模型实际看到的上下文。

“检索无结果”“页面取得失败”“已取得内容但无答案”分别记录。未返回的材料不是已判无关，模型引用也不证明网页支持。article_042实际抓取正文并以jusText清理，论文不给模型URL等元数据；本章要求研究记录保留出处，不将它说成论文已经向模型提供。检索评分及语义匹配见[K03](K03_text_semantics.md)。

<a id="k07-05"></a>
## 05 摘要记忆与主动读写

摘要记忆先确定从哪些轨迹挑选信息、摘要目标与写入时间，将摘要与原轨迹ID关联；下一轮明确读哪些摘要及长度预算。更新可以替换活跃摘要，但研究记录保留更新前后版本；不能把摘要中新增的解释当原事件事实。

主动外部记忆需要读/搜/增/改函数及对象标识：收到函数调用→检查参数→访问实际存储→回收结果→把结果放回当前上下文。核心记忆是随提示可见的部分，archival/recall须主动查询；只保留聊天历史不等实现外部读写。定义查询无命中、同名条目、更新时间与失败写入，区分缓存、遗忘策略和语义内容。

article_010总结经营并从后续反馈更新策略，article_242对比被动MemoryBank与主动MemGPT；两者都不自动意味着模型权重训练。

<a id="k07-06"></a>
## 06 贡献估计到协商结算

将贡献估计作为提案输入，保留提案者、对象、份额/转移、接受/拒绝/反提案及当前协议版本。只有按共同规则接受后才生成最终结算；检查总额和既定可行约束，未成交按预设回退处理，不能自动用贡献公式强行结算。

article_153短期合作协商、长期轨迹贡献估计及最终分配是相连但不同阶段。最后份额来自协商而非必然等于Shapley，近似贡献与实际支付须分别报告；公开示例不是全套执行模板。

保留最后一次被各方接受的提案编号。若本轮只有反提案而无共同接受，按无协议的约定结算，不能用最后一个出价填为成交；实际出资或支付由环境回执记录，并和模型在发言中的承诺分别对照。

<a id="k07-07"></a>
## 07 评分驱动的自适应配对

维护未纳入集合U、已纳入集合R、所有成对结果、当前BT参数及已赛对手表。article_225的SWIM先随机初始化R，再随机取新对象P；令s=|R|、`c=ceil(max(log₂s,1))`，先随机选一个R内对手比较，立即重拟合BT；余下c−1轮在未与P比赛者中选择`|β_O−β_P|`最小者，比较后再次拟合，最后P入R。

每轮选择依赖此前结果，必须保存“选择前”的强度和候选对手集合。不能先用最终强度安排全部对手却称同算法。随机种子、同距破同分、拟合失败和无可选对手须声明；与按累计积分分组配对的Swiss赛制、预先列全对手的全循环赛区别见[K05](K05_evaluation.md#k05-06)。

<a id="k07-08"></a>
## 08 KV分区、事件队列与attention衔接

长上下文缓存先明确初始sink、近期局部窗口和移出的历史事件三部分，保留每个token的原序列位置、层、key/value及事件身份。每层从历史检索事件，把其KV与sink/局部KV拼接，使用声明的位置编码及mask进入该层attention；避免重复token在两处被重复赋质量。

article_177对不连续检索token使用固定位置embedding，另有contiguity队列保存检索事件的原序列±n邻居。每次新检索后按协议去重、移出旧项，按token预算而非事件个数填充`k=k_s+k_c`，事件长度不同会影响可容纳数。各层独立检索，不能把一层结果当所有层共用；队列改变上下文，固定模型权重不意味着与完整上下文前向等价。

<a id="k07-09"></a>
## 09 KV迁移与跨设备执行

为缓存槽保存事件/层/token映射和所在设备；命中更新LRU，容量不足时选择可迁移槽，完成GPU→CPU/磁盘搬运后再复用。取回前等待数据可用，层计算完成前不能覆盖仍被引用的槽。记录传输、缺页、精度及峰值内存；预分配减少碎片不保证没有传输延迟。

跨GPU按层执行时，保持层顺序和中间激活/缓存设备一致，测总延迟需含搬运。article_177的具体offload阈值与Accelerate分层设置是其实现，不是通用要求；本章仅补执行关系，不在当前项目搭建这套运行平台。

<a id="k07-10"></a>
## 10 等待调度、回调与虚拟时钟

调度器保存任务状态：可运行、运行中、等待时间、等待token、回调待触发、完成。选择满足兼容关系的任务；当前任务运行到结束或让出，再优先恢复条件已满足者，最后启动新任务。所有任务阻塞时按协议推进时间或填充token；记录等待目标从哪个基点计数，消息/回答是否都计入token。

回调的注册、触发条件、有效期、重复触发、取消和任务结束后清理须明确；提前出现、漏触发与正确时点响应分别计分。article_242的isolated仍可能执行用于触发回调的filler，不能只按“隔离”标签省略这些实际步骤。

虚拟时间只改变所控制进程可见的时钟：统一当前时间、跳跃幅度和同机agent读时接口，触发所有到期等待。外部服务或不兼容agent仍按真实时间运行，应回退真实等待，不能伪称跨系统时间已推进。保存虚拟/真实时间及事件序列，避免用墙钟耗时解释虚拟延迟任务。

逐项实例与来源见[逐项对应](TRACEABILITY.md)。一条完整轨迹应能说明每一步输入、状态改变和结果来源；不要求另建与现有记录重复的文献权威库。
