# 用机器行为文献训练组件知识库的方法

**方法标准 v1.4，2026-11-25。** 本文完整说明怎样从机器行为论文识别知识缺口、提炼补法、修订组件用途，并形成可以直接使用的组件手册。具体判断依据、补充深度和成品要求在同一流程内说明。

## 研究目标、材料与产物

训练对象是研究者查用的**组件知识库**。我们用机器行为研究中的实际做法检查原库：有用但不完整的知识补全，缺少的方法补入，原有组件的用途按机器实验重新审视。这里的训练是对知识内容和组织方式的修订，不涉及模型参数训练。

本轮以原69项实验组件及构念与任务附录为起点。原库以传统实验方法为基础，已经包含20项大模型专项；这些原有知识不能算成本轮新增。开发材料是已完成事实提取与覆盖分析的243篇论文，现有分析归并出381项具体知识缺口。另109篇保留作评测候选，未用于这项训练。组件面向机器行为研究，本阶段不为真人对照组编写设计指导；人工评价模型输出等直接服务于机器行为测量的操作可以纳入。[原手册](../../../analysis/literature_component_coverage/baselines/实验组件_v1.4.md) · [构念与任务附录](../../../analysis/literature_component_coverage/baselines/实验设计原则清单v1.6_相关构念与任务.md) · [缺口与分析口径](../../../analysis/literature_component_coverage/data/gaps.json)

交付两件成品：**本方法标准和完整组件手册**。随组件库保存一份集中改动记录，说明实际改了什么、为什么改、依据在哪里。已有K文件保存按方法组织的知识，可直接复用；它不是必须重新制作的一道工序，也不代替完整组件正文。效果评测、skill化与智能体架构属于后续工作。

论文事实、方法需求、知识缺口和组件不是一一对应。一篇论文可以提出多项需求；不同论文的需求可以暴露同一个缺口；一个缺口也可能需要多个组件配合解决。**用缺口编号明确要补什么，用关联实例识别条件差异，用组件正文承载可复用知识。** 原编号与证据联系沿用现有记录，不因重新组织正文另造一套缺口。

## 完整方法

**论文中的实际做法 → 对照原库识别缺口 → 提炼补缺方法 → 修订组件用途 → 形成完整组件正文 → 核对并定稿。** 补方法与审视组件用途可以并行，相互提供依据；形成完整正文是训练本身的一部分。

### 1. 从论文实际做法形成方法需求

先确认作者实施了什么，而不是从论文主题猜测它应当使用什么组件。阅读时分清操作对象、输入材料、比较或控制方式、产生的输出，以及作者如何计算或解释结果。方法需求描述完成这项操作所需的知识，例如“比较同一批对象在两个条件下的差异”，而不是只记一个方法名称。

事实提取与组件判断分开：A记录保留事实和原文证据，B记录基于这些事实说明方法需求及原库的支持情况。实际操作、作者讨论的可能做法、整理者的解释和未报告信息分别记录。原文没有交代某项设置时，即使知道规范做法，也不能据此认定作者已经采用。

本轮243篇已完成这一步，后续补库沿用这些记录。遇到实例说明不清、证据不足以支持判断或原文与记录不一致时，沿相关需求回到A事实和原文定向核对；发现事实错误修正事实记录，只有方法归属或组件判断需要调整时，不改写原论文事实。对一篇论文的局部复核，不扩写为重新完成全篇提取。

**这一步提供的依据：** 能从具体方法需求找到论文、事实与原文位置，并分清已实施内容和未知。只有这些依据清楚，才能进一步判断库中是否缺少知识。

### 2. 对照原库，明确缺口的内容与范围

本轮从现有381项缺口出发。逐项读取“已有支持、所缺知识、影响”和关联论文需求，再到原组件及附录中核对能够回答问题的具体句段。原记录中的建议承接组件用于定位材料，不能代替实际阅读。

一项缺口需要说清三个相连的问题：**研究要做什么，原库已经能指导到哪里，还缺哪一步及其后果。** “支持不充分”不足以说明缺口；应具体到缺少的输入处理、操作步骤、计算关系、条件或解释依据。

| 核对材料后的情况 | 方法上的处理 |
|---|---|
| 原库已把必要做法讲清楚 | 复用已有知识，记录出处。相关内容若是使用新版组件所必需，融入新版正文；不计作新发明的方法。 |
| 已有原则或部分做法，但缺关键步骤或条件 | 指出已有部分和剩余部分，补足会影响实际使用的内容。 |
| 原库没有相应做法 | 从论文需求和方法依据提炼所缺知识，再判断由哪个组件承接。 |
| 论文没有报告必要设置，暂时无法确定其实际操作 | 保留论文实例的未知。若同时缺少处理这类不确定性的通用指导，可补指导，但不替论文补认设置。 |
| 实例仅服务于真人参照，没有机器侧用途 | 记录对象和依据，列在本轮范围外。一个缺口若还有机器侧实例，继续处理机器部分。 |

**缺口归并按实际操作和条件判断。** 不同论文需要同一步骤，输入含义、分析单位和适用条件也一致时，可以共用一个知识点。名称相近但独立样本与配对样本、题目与会话、完整概率与受限接口读数等条件不同，不能直接当作同一种操作。已有编号保留，必要差异在该编号的说明和正文中展开。

同一缺口关联多个实例时，查看各条实例说明，识别会改变输入、操作、输出含义或解释条件的差异；对这些差异核对相应B判断、A事实及必要的原文。不能读一个代表实例就默认覆盖其他情形。反过来，不因题材、模型名称或一次实验参数不同，就重复建立同一条通用规则。

**这一步形成的判断：** 每项明确机器侧要补的知识、已存在的答案和剩余问题；不适用项说明理由，未知项保留具体疑点。

### 3. 提炼能够补上缺口的通用方法

按实际操作的关联组织阅读：共用方法段落、共用证据或存在先后依赖的缺口可以一起处理。共同阅读和写作不免除逐项判断；一段方法可以同时回答几个问题，每个编号仍须有实际答案。

先从最可能回答问题的原条目、附录或已有K段落读起，核对是否真的满足缺口的操作和条件。答案充分、出处清楚的直接采用；只有部分答案的，保留正确内容并补足缺步；有冲突或位置错误的，回到相关条款与方法来源解决。记录时区分原库已有、已有训练知识可复用和本次实际修改，避免把同一知识反复算成新增。

#### 一段方法要讲到什么程度

篇幅由缺口决定，但必要的做法应当能够从正文读明白。

| 要讲清的内容 | 具体要求 |
|---|---|
| 适用的问题与条件 | 什么时候使用，处理的对象是什么；与容易混淆的方法如何区分。 |
| 输入与分析单位 | 输入有哪些，来自哪里，按题目、会话、模型、评分者或其他哪种单位组织；相关或配对关系怎样保留。 |
| 关键操作 | 按实际依赖说明步骤，上一步得到什么、怎样进入下一步。只有选择原则的内容，写清判断条件及相应处理。 |
| 计算关系 | 需要计算时，交代变量含义、分子分母、聚合或加权方式、方向及必要的取值约定；不能只给算法名称。 |
| 输出与解释 | 得到什么结果，可以回答什么研究问题；哪些结论还需要其他条件或证据。 |
| 易错情形与检查 | 对会改变结果的缺失、无效输入、受限接口或边界情况说明处理办法，并给出能够发现这类错误的检查。 |

不是所有组件都要包含公式，也不要求每项研究使用手册中的全部方法。只缺一句条件就补清这一句，缺少完整操作才写完整步骤；可选方法明确其使用条件，不能因某篇论文采用过就写成所有研究的必选项。具体模型名、数据材料、阈值和随机种子通常留在实例中，只有确实影响方法含义时才进入通用规则。

#### 不同来源分别支持什么

开发论文和A事实支持“作者实际怎么做”；原始方法文献、作者实现及官方文档支持可复用的定义、公式、接口语义与条件。优先复用已有来源，原有依据不能解决具体问题时，再针对该问题补查。论文中的某种实现可作为实例；是否适合推广，需要核对其成立条件。

原库、K方法和论文实例有冲突时，先检查是不是输入、单位、适用条件或版本不同。条件不同就分别说明；同一条件下确有错误，按方法依据改正，不能仅因某段更早或更晚出现就优先采用。影响组件用途或解释的重要取舍在集中记录中交代原因。

人类实验术语可能引起误解时，用实际观察或控制到的模型行为描述。可以讨论类比，但不能从“长输出出现重复”等现象直接推成具有人类意义的疲劳。若主张人与机器测量的是同一构念，需要相应的测量依据；本轮不据类比编写真人对照方案。

**这一步形成的内容：** 能回答缺口的输入、做法、输出和条件，以及相应来源。已有K知识直接用于修订；新补知识也可直接写进组件，不要求先制作新的K文件。

### 4. 审视原组件的机器用途，决定怎样修订

补知识以缺口为单位，审视用途以原69个组件为单位。不能只检查旧缺口映射涉及的组件：没有被分配缺口的条目，也要结合原条款、机器侧用例和相关知识判断是否需要修改。

先读清原条款解决的问题和操作对象，再查看实际采用或控制该做法的论文。报告频次时按同篇同组件去重，仅供检索的关联不计实际采用；人机比较研究按具体操作区分两侧。原使用表的关联数可能包含真人侧操作，未经核对不能直接称为机器侧使用次数。人工标注模型答案是否正确，按其直接参与机器行为测量的用途处理。

**频次和适用理由分别判断。** 低频或零次说明在这批文献中少见，可以提示复查，但不能单凭频次删除。只要能说清解决哪种机器问题、有何依据，就可以按相应条件保留。仅适用于真人的内容可以移出；同一条目兼有真人与机器内容时，分别处理，不能整段一并删去。

| 判断 | 对组件怎样处理 |
|---|---|
| 原职责仍有机器用途，现有内容已充分 | 保留正确内容，检查它与新增方法的衔接。 |
| 原职责适用，但操作、条件或说明不全 | 在相应位置补足，必要时同步定义、例子和判定要求。 |
| 原名称或解释过于拟人，但有明确机器操作 | 按可观察的对象和行为改写，说明适用条件。 |
| 两项承担重复职责，合并后仍能保留各自有效内容 | 合并到明确的承接组件，记录旧编号及独有内容的去向。 |
| 只有真人侧用途，或有效职责已由其他组件承接 | 提出移出独立目录的理由，保留原编号、依据及机器侧内容的承接位置。 |
| 确有独立的研究职责，现有组件及其组合均无法承接 | 说明独立问题、与相邻组件的区别及现有安排会漏掉什么，再提出新增建议。单个算法或工具名不自动成为新组件。 |

组件去留由项目负责人与整理者共同决定。当前沿用已经确认的69→65结构；补充方法、改正文及消除矛盾可以直接推进，确需改变已确认的职责或组件结构时，再说明具体影响共同讨论。保留原职责不等于正文原封不动。

组件的操作说明与论文质量评分分开。新增一种分析方法，不自动要求所有论文使用它，也不自动提高原论文覆盖等级。若确实要改变同一事实下的评分判定，应明确提出受影响条目及新旧判例，另行决定；不在正文修订中暗改既有评价口径。

**这一步形成的决定：** 在集中改动记录中按原编号说明机器用途、依据、取舍和实际去向。合并或移出的条目中，仍有效的机器操作要能找到承接段落。

### 5. 将原有知识与补缺方法融成完整组件正文

形成正文前，阅读覆盖原始手册、相关附录、全部已有K知识及已确认的组件去向。已读清的内容可直接用于写作，不因换一批重复通读。按知识关联安排写作，相关组件可以一起整理。

以组件实际承担的问题组织内容。先确定它在机器实验中观察、控制或判断什么，再把适用条件、必要步骤与计算、解释和检查要求融入相应段落。正确适用的旧内容保留，遗漏内容补足，错误或冲突说法改正，重复内容归并。修改规则后同步例子、报告要求和编码判定，使同一组件内的说明一致。

**融合后的成品必须自足。** 读者从新版组件手册就能了解必要的做法，不需要先翻K文件、旧附录或历史讨论。已有知识可以复用，但最终需要的方法和任务规则必须进入组件正文；原出处链接用于查依据。原字段所承载的有效含义应当保留，组织和措辞按使用需要调整，不以逐字段机械追加代替内容融合。

跨组件的知识按职责分工：共用的完整方法放在主承接组件，其他组件交代本地使用条件、必要操作及衔接，链接到同一本手册的具体段落。一项缺口若跨多个组件，在同一条记录里说明各部分负责什么。不同条件下的做法分别交代；便于理解的简短重述可以保留，不为追求零重复把条目拆碎。

例如，同一任务在两个条件下比较时，设计组件负责配对与状态安排，测量组件负责输出怎样计分，统计组件负责怎样保留这种关系并计算差异。共同使用一个方法不意味着几个组件都应重复承担全部计算职责，也不能只写一个链接而不说明本组件如何使用它。

**这一步形成的成品：** 完整组件正文和同版本集中改动记录。K知识已写好、目标组件已分配或旧摘要已加链接，都不能代替这一步。

### 6. 对照缺口、原组件和实际正文核对定稿

从三个角度对照：原缺口要求的知识有没有答案，原组件中仍有效的内容有没有丢失，共用方法在相关组件之间是否接得上。涉及同一方法的条目一起读，检查操作、适用条件、例子、计算与解释是否互相矛盾；有具体问题就修正文或定向查依据。

逐项判断是否解决时，区分以下情况：

| 实际情况 | 如何记录 |
|---|---|
| 必要知识与条件已讲清，已有依据，完整手册中能找到 | 记录实际正文位置；多个缺口共用一段可合记，但每个原编号都有去向。 |
| 部分内容已经写入，但仍缺关键步骤或通用依据 | 保留待补，指出缺什么及下一处需要查的材料。不能因已有段落就整项结清。 |
| 通用规则已经完整，仅某篇论文的参数或操作设置未报告 | 可结束知识补充，同时保留该论文实例的未知，不虚构作者做法。 |
| 尚未读取或处理 | 记未处理，不伪装成已核实的未知或范围争议。 |
| 已确认仅属真人参照等本轮范围外内容 | 记录范围理由和实例依据，不写成机器组件的普遍要求。 |

核对按381个原缺口编号及69个原组件编号覆盖，并检查原条目与K知识中的有效内容。旧映射不是穷尽目录，不能因为某段没有分配缺口就跳过。合并和移出的编号有去向，已采用组件有实际正文，必要问题已经解决，才形成定稿。尚有关键知识或结构决定未完成时，保存工作版并明确余项。

阅读和修订过程中可以同步核对，收尾集中处理跨组件衔接、遗漏和未解决事项，不规定反复审核轮数。程序用于检查编号、引用、重复记录和统计，不能从链接存在或队列为空自动生成内容已通过的结论。同一整理者的复核按实际身份记录，不称独立同行评审。

## 用现有材料说明几种判断

这些例子分别展示从实例判断缺口、确定补充深度和决定组件去向的方法；其中论文事实和手册规则各有自己的依据。

**配对重抽样和百分位端点：共用一节，分别回答。** `KG_BOOT_PAIRED`要求保留配对关系，`KG_BOOT_PERCENTILE`要求说明区间端点如何取得。前一个问题不能由“计算百分位数”回答，后一个也不能由“按配对重抽”回答。第237篇的A记录F016及E049保留了排序后按下标取端点的作者代码；手册应由此说明需要明确有限次重抽的取位或插值约定，而非把该篇的固定下标推广到所有实验。两项在成品中共同落到[F1重抽样方法](COMPONENTS.md#f1-bootstrap)，各自的来源与去向仍可查。[配对缺口](CHANGES.md#gap-kg_boot_paired) · [百分位缺口](CHANGES.md#gap-kg_boot_percentile) · [237号事实与代码证据](../../../analysis/literature_component_coverage/records/extractions/article_237.json)

**候选词概率：同一缺口里的接口差异不能省略。** 第044篇原文说明接口只能返回已生成token的概率，作者通过不同强制补全重复生成同一输入。这样的实例与能够直接取得多个候选词概率的接口需要分别说明取数条件。通用规则应交代可获得哪些值、如何处理未返回候选项，不能默认所有接口提供同样完整的读数。[044号原文](../../../literature/selected_no_model_adjustment/texts/article_044.txt) · [A2概率读数](COMPONENTS.md#a2-12)及[受限接口](COMPONENTS.md#a2-13)

**多评分者一致性：不同缺口可以共用正文。** `KG_FLEISS`与`KG_REL_FLEISS`在现有集中记录中都指向[F3多名类别评分者](COMPONENTS.md#f3-03)。共用同一计算说明不需要写两套公式，但各项保留自己的论文依据。如果某篇只报告“κ”，仍不能根据评分者人数替作者指定为Fleiss κ。[两项缺口及来源](CHANGES.md#gap-kg_fleiss)

**n-back：复用原库，也要让成品讲全。** 第199篇关联的通用匹配判据在原构念附录已有说明，故不应把它记为新发现的方法。新版将必要任务规则写进[A7的n-back说明](COMPONENTS.md#a7-16)，使读者不必另查附录才能使用。论文自身的序列、实现和未报告设置仍依该篇证据判断。[该缺口的原依据与成品位置](CHANGES.md#gap-worker_2_nback_generation_gap)

**D2与J12：频次提示审视，机器用途决定取舍。** D2原关联中的第059篇限制每名真人众包答题者最多回答20题，以维持注意力并防止答题者偏差；该措施属于真人侧。D2原条款中的长上下文位置、长输出重复等机器操作仍保留，由J7、J9等条目承接。J12在原使用表中实际采用为0篇，但模型得分接近基准上限时仍需要判断区分度，因此保留这一机器用途。两项按已经共同确认的决定处理。[059号原文](../../../literature/selected_no_model_adjustment/texts/article_059.txt) · [原使用统计](../../../analysis/literature_component_coverage/tables/components.csv) · [实际改动与去向](CHANGES.md)

## 改动记录、交付与本轮事实

随手册保留一份[集中改动记录](CHANGES.md)，能查到：**关联缺口与原组件、原有内容和不足、实际修改及理由、论文与方法依据、成品位置，以及未完成时的具体余项。** 重要的跨组件分工和原编号去向也记在这里；不逐句另建记录，不并行维护多份改动报告。

一段正文解决多个缺口，可以合并说明但保留原编号；一个缺口涉及多个段落，交代各段职责。正文位置和来源变化时同步相关引用。中断后从记录中的未处理项与待补项继续，已读清的证据和正确正文直接复用。已发布快照、原始手册、原K文件及原论文证据保留；现行入口、版本和下一步在项目工作记录中管理；本次发布内容及版本关系见[阅读入口](README.md)。

现有融合定稿包含65个独立组件，原69个编号的取舍与去向均在集中记录中说明。381项缺口中，379项有完整手册内的正文落点，2项保持已确认的机器范围外结论。保留组件职责与保留旧文不动是不同的统计口径，不能据“保留”数量推断实际改写量。本轮没有重新计算论文覆盖率，也没有完成新旧库效果比较；当前可报告的是知识内容、组件去向及正文融合的结果。

本文v1.4依据旧版方法标准、现有证据和完整正文补全方法说明，不表示重新执行了一轮训练。11月25日组件正文及集中改动记录保持不变；本次将随附方法标准更新为v1.4，v1.3可从Git版本历史及原发布快照回查。
