# 整理标准与字段说明

## 1. 先提取论文做了什么，再判断组件能支持什么

A阶段不填组件ID、覆盖等级或修订建议；B阶段引用固定版本A的事实和证据。分类变化在B处理，只有真实的事实错误或遗漏才定向修正A。本包保留已有判断，不从关键词自动生成结论。

**研究流程单元**（数据中的units）是能够说明目的、任务程序、条件、观察结果和分析关系的一段研究流程。正式行为实验、辅助评分、材料生成和后处理分别标识；共享流程可以服务多个单元，但不额外变成一个独立行为实验。单元之间可共享数据或输出，并不一定相互独立。

**方法事实**是论文报告的一个可核查陈述，例如“提示设置三种条件”“选项顺序进行了平衡”“正确率按题计算”。一条事实可关联多个单元，多条事实共同说明一条实验链。事实本身不必是一整条链，也不按每篇固定条数拆分。

拆分以判断需要为准：若两种操作的功能、组件贡献、覆盖等级、缺失知识或适用边界不同，必须分开；只是故事、模型名称、参数取值不同且不改变方法含义时，不额外造方法类别。原文事实、解释、建议和未知分开；讨论某风险不等于实施相应控制。

## 2. B如何对应组件

B把相关事实整理为方法需求，写明适用单元、实际方法/实际控制/报告等角色、F事实ID和E证据ID。M01—M10只是检索标签，不是替代69项组件的新组件库，也不是唯一覆盖分母。

每项分别判断：

| 维度 | 含义 | 值 |
|---|---|---|
| 组件知识支持 | 基线是否支持相应方法在指定深度的含义、操作/计分和适用边界 | full / partial / none / uncertain |
| 论文报告 | 论文是否报告了自己的实现 | complete / partial / conflicting / not_reported |
| 复现影响 | 报告缺失或冲突对复现的影响 | none / limited / substantial / blocking |

`full`要求一般知识已足以支持被评价的方法功能；手册没写某论文的具体故事或参数，不构成缺口。`partial`必须明确已有X、缺少Y、影响Z。`none`必须在检索基线后确认指定深度缺少支持。资料或边界无法确定时为`uncertain`，不当作缺失，也不从分母删除。

两套基线是v1.4核心69项，以及核心加v1.6构念任务附录；附录只有带来实质支持时才改变等级。第三份rubric保留作材料分工参考，不把论文设计评分等同于知识覆盖。

一个需求可以需要多个组件。各组件分别保留窄贡献、等级、条款和证据；不能把需求的整体等级复制给所有组件，不能把某项算法缺口分摊成所有关联组件的缺陷。只用来查找边界的 `search_reference` 不计实际关联。

## 3. 跨论文怎样归并

已有需求按方法机制与实际功能对应方法族及规范方法。同名但操作、输入结构、输出目标或适用条件不同，不自动合并；名称不同而方法相同，可以在保留实例差异的前提下归并。登记目录不等于实际观察数，主表只列本轮实际出现的566种已识别方法。

一个需求包含多个必要子功能时，保留各子功能等级和父需求整体等级，并说明差异。一个子功能充分不能使整个需求充分。功能记录的 `fulfilled_support` 是明确的组件支持，`gap_ids`指向具体缺口；未知方法保持空ID并解释原因。

同一知识缺口归并成一条可补充的知识点，记录X/Y/Z、评价深度、建议承接组件及依据。建议承接位置按方法功能确定，不按组件关联排列顺序决定；它不是现有组件使用记录。没有必要为了每个算法新增一个顶层组件。

## 4. 计数口径

当前243篇共1,430个研究流程单元（965个研究/分析、297个辅助、168个共享流程）、6,585条方法事实、14,024条原文证据和6,214条方法需求。单元数不是独立实验数，事实记录也不保证每条只含一个最小操作；原始证据可以被不同方法判断复用。

主要统计为5,479条范围内实际方法或控制需求：5,415条已归族并核完登记功能，64条经本轮核查仍无法归族，保留未知。对应6,274个功能关联、566种已识别方法。其余106条范围外、97条范围不明的实际需求以及532条报告类需求保留在B，不混入主分母。报告类34条已有某些功能细化、495条仍有待细化内容，二者重叠3条，不是互斥分组。

| 需求层知识支持 | 核心69项 | 核心加构念任务附录 |
|---|---:|---:|
| 充分 | 4,143 | 4,144 |
| 部分 | 454 | 453 |
| 未覆盖 | 446 | 446 |
| 未知 | 436 | 436 |
| 合计 | 5,479 | 5,479 |

381项归并知识缺口在核心基线下为120项部分支持、261项未覆盖；加入附录后其中1项获得充分支持，其余380项仍有缺口。缺口等级须连同评价深度阅读：例如一般测量原则已有，但专门算法的操作规则未覆盖，并不表示整个测量组件没有知识。

| 统计量 | 去重/分母规则 |
|---|---|
| 组件关联论文数 | 范围内实际需求，同篇同组件一次；跨组件不能相加 |
| 去重需求数 | 同篇同需求同组件一次 |
| 窄贡献关联数及等级 | 保留记录中不同贡献；可多于去重需求数 |
| 需求支持分布 | 5,479条范围内实际需求，F/P/N/U互斥，未知计入分母 |
| 方法功能数 | 每个登记的需求×功能关联；不可与需求数混用 |
| 方法表论文数 | 同一方法同篇去重；等级列按功能关联计数 |
| 缺口论文数 | 同篇同缺口去重；一篇可涉及多个缺口 |
| 缺口需求实例数 | 同一缺口下同篇同需求去重 |
| 领域 | 正式研究单元判定，多标签；文章取标签并集，比例可超过100% |

不把partial赋0.5，不生成任意加权总覆盖率，不把论文缺报当作组件知识缺失。441条需求含至少一个功能/输入未知，与436条需求整体未知是不同层次；64条已核无族需求包含在主分母中，但不虚构成已知方法或具体缺口。

组件表同时列出去重需求数与窄贡献关联数。例如235号D046对A2分别记录评分规则和比例计算两条充分贡献，因此A2有1,799条充分贡献关联；不能与需求去重后的数量混称，也不能把贡献等级当作组件整体成熟度。

组件表“参与支持的常见方法（示例）”从现有核心基线full功能的明确组件关联中，按涉及论文数取最多两种方法；名称照录现有方法定义，只作阅读例子，不代表该组件独自支持整个方法，也不是新评分。示例依据链接取第一种方法的一篇已有记录；完整关联仍在B。没有例子不自动表示没有部分贡献。

方法表的组件列汇总不同实例明确登记的充分支持，不表示每篇都使用全部所列组件。“未列出充分支持组件”只说明本列没有充分支持记录；是否存在部分支持，要看等级与B中的窄贡献，不能直接理解为none。建议承接组件另列，不计现有使用频率。计数、ID和等级与现役记录一致；中文组件名来自锁定索引。代表依据仅为方便打开一篇记录，其他依据见同一行论文ID及文献表。

CSV中的A/B路径相对tables目录；工作簿把相同目标显示为可点击的简短文字。其余JSON路径仍遵循下节的包根规则。两者显示形式不同，统计数值和链接目标逐项核对。工作簿先排组件、缺口，再排方法明细与文献；不新增平行结果表。

## 5. 程序读取与证据定位

所有包内 `path` / `extraction_ref.path` / `clause_file` 均相对**本目录根**解析，不相对所在JSON文件。`url`为外部链接；`origin_sha256`仅标识本地权威源记录，不是当前导出文件的哈希。共享schema为 `shared_extraction_v1` 和 `shared_assessment_v1`，不可直接套用本地生产schema。

| 位置或字段 | 含义 |
|---|---|
| `data/papers.json` | paper_id、标题、固定版本PDF链接、A/B及条款文件入口 |
| A `units` | 单元身份、角色和研究流程；U编号仅在同篇内唯一 |
| A `facts` | F编号、事实陈述、适用单元、证据ID及事实性质 |
| A `evidence` | E编号、source_id、原文quote、页码/行号；不是模型自行生成的论文原句 |
| A `sources` | 原件URL或包内附加证据路径、内容身份、版本与用途 |
| A `issues` | 缺报、冲突、证据限制及其影响 |
| B `domains` | 原始领域判断与校准后的domain_ids、适用单元和依据 |
| B `demands` | D编号、需求、角色、fact_ids、evidence_ids、适用单元及三种独立判断 |
| B `coverage` | 双基线整体等级、mapped_components及各组件窄贡献、检索和理由 |
| B `consolidation` | 范围、方法族、precision及additional_functions、未知说明 |
| B `fact_handling` | 每条A事实在B的处理去向 |
| `evidence/clauses/` | 同篇clause_refs对应的手册原句与基线行号 |
| `data/method_definitions.json` | 方法、领域、方法族和评价深度定义 |
| `data/gaps.json` | 缺口X/Y/Z、承接理由、实例、双基线与附录作用 |

E/F/D/U编号需连同paper_id使用，例如 `article_014/D214`。功能键在此基础上加方法族ID。PDF页码是物理页码；代码文本通常把全文件视作第1页，行号定位源码。转换全文未随包导出，PDF的文本行号只作原提取定位，优先用页码和quote核查；代码证据可直接按行核对。

5篇早期单来源记录的392条证据未逐条重复写source_id，均对应该篇唯一来源；读取时只在sources恰为一个时采用此规则，多来源记录必须显式指定。导出保留原始证据字段，不补造新版本。

共享A保留全部单元、事实、证据、问题，B保留全部需求、领域、事实去向和现有覆盖判断。删去的是执行计时、历次变更和本机路径依赖，不删未知、无映射、范围外或报告类记录。原件与转换件的哈希不混用。当前条款原句及附加原件一并保留，避免引用一个合作者拿不到的本机目录。

此共享包支持读表、追证和进一步讨论组件补充；不包含实验执行平台，不证明文献中方法均推荐使用，也不证明已获得新论文泛化能力。

`evidence/sources/`中的作者代码和README是本次引用到的原件片段，不是作者仓库的完整可运行副本；它们内部提及的模块、图片或相对链接仍属于原作者仓库，不作为本包依赖。包内入口、A/B证据来源与手册条款的引用均单独核对。

## 6. 文件分工与共享边界

| 位置 | 用途 |
|---|---|
| tables/ | 四张CSV与同一份工作簿；无需同时阅读两种格式 |
| records/extractions/、records/assessments/ | 243篇A事实、B对照；保留全部科学判断和未知 |
| data/ | 文献/组件/方法定义、归并缺口与统计摘要 |
| evidence/clauses/、evidence/sources/ | 当前引用的手册条款，以及必要附录/补充代码原件 |
| baselines/ | 锁定的手册v1.4、构念任务附录v1.6及rubric副本 |
| release.json、validation.json | 来源身份、核对版本与导出验证结果 |

主文PDF复用远端literature/selected_no_model_adjustment/，固定提交链接保证编号与内容对应。旧筛选账本、延期任务、API日志、转换全文、截图缓存和历次返工记录不在共享包中。作者代码只作静态证据，不表示已运行实验。

仓库目录为analysis/literature_component_coverage/。远端coding/results/使用1/0.5/0/NA/NR评价论文设计与报告，本包评价组件知识支持，不能互换等级或覆盖现有评分。共享投影不作为本地恢复状态；审阅含项目内助手协作，不称外部独立评审。导出一致性检查不等于重新科学验收，也不单独证明拆分粒度合理。
