# 从243篇文献看组件支持与知识缺口

我们用已入选文献检查两件事：**69项组件哪些常用、具体能支持什么；还缺哪些知识、适合补在哪里。** 当前完成了文献提取与覆盖对照，补充建议尚未写入手册。

## 先看两张结果表

打开[可筛选工作簿](tables/组件覆盖与补缺.xlsx)，先看“69项组件频率”和“具体知识缺口”。

| 要回答的问题 | 看哪里 | 怎么读 |
|---|---|---|
| 哪些组件常用、支持什么？ | [69项组件频率](tables/components.csv) | 按关联论文数看频率，结合常见方法示例理解贡献；不能跨组件相加 |
| 具体缺什么、补在哪里？ | [具体知识缺口](tables/gaps.csv) | 共381项，逐项列出已有支持、缺少的知识、影响和建议承接组件 |

需要深入时再看[方法与组件关联](tables/methods.csv)。核查某项结果，可点工作簿的“依据（B）”；查其他依据论文，在工作簿“文献与领域”页打开其A事实、B对照和PDF（另有[CSV索引](tables/papers.csv)）。

**知识覆盖不等于实验复现成功；381项知识缺口不等于要新增381个组件。**

## 为什么要拆？单元、事实、需求是什么？

不对整篇论文笼统判“覆盖/不覆盖”，而是分别检查抽样、条件、计分等做法需要的知识。三个名称分别回答不同问题：

| 名称 | 含义 | 001号论文的真实例子 |
|---|---|---|
| 研究流程单元 | 论文有哪些研究、分析或辅助流程？ | 解法生成、分层分析、模型间比较、评审、材料整理，共5个；不是5个独立实验 |
| 方法事实 | 作者具体怎么做？有何原文依据？ | 每个竞赛随机抽50题；按顺序增加参考解法；限制输入长度 |
| 方法需求 | 对照组件时，分别要检查哪些知识？ | 抽样对应C1随机化等；条件设置对应A1自变量/A8水平；共同设置对应C3恒定等 |

这篇研究考察模型能否提出新颖数学解法，保留了20条事实、19条需求。看[001号A事实](records/extractions/article_001.json)中的F003/F004，以及[001号B对照](records/assessments/article_001.json)中的D003/D004/D012，可核查上述例子。一条事实可被几个需求引用，一个需求也可综合几条事实，并非逐层切成互不相干的碎片。

**主统计的5,479条，是243篇论文中的方法需求记录，不是5,479种方法或独立实验。** 同一种方法在不同论文中分别留证，再跨论文归并。改变操作、计分或适用边界才需要分开判断；仅换故事、模型名或不改变机制的参数，不自动另造一项。数量本身不能证明拆分合理，判断要回到实际做法和依据。
